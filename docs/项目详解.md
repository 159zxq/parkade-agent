## 1. 项目总览

用户用自然语言对话，Agent 自主调用工具完成停车业务（识别车牌、查车位、登记入场、
计费结算、预约、缴费），规章问题走知识库 RAG（附引用编号），费率**解释**走知识库、
费率**计算**走工具（防算术幻觉）。

### 1.1 系统组成（两个进程 + 三类存储）

```
┌─────────────────────────── 浏览器 ───────────────────────────┐
│  Vue3 前端（用户 | 对话 | 车牌识别 | 缴费+车位看板）              │
└──────────────────────────────┬───────────────────────────────┘
                       HTTP /api/*（含静态页面）
┌──────────────────────────────▼───────────────────────────────┐
│ server/app.py —— Web 服务 :8100                               │
│  用户/消息管理 · 聊天入口 · 上传识别 · 看板代理 · 静态托管         │
│        │                    │                                 │
│        │ chat_with_context  │ recognize_upload（管理端识别栏）  │
│        ▼                    ▼                                 │
│  Agent（langchain create_agent）        双通道识别（本地OCR∥视觉）│
│   ├─ 4 个工具 ──────────► HTTP ──────► mock 服务 :8000         │
│   └─ RAG 中间件 ─────────► Chroma 向量库（kb/chroma_db）         │
└──────────────────────────────────────────────────────────────┘
                          mock_service/main.py —— 停车场模拟服务 :8000
                          车位/出入场/预约/缴费/相机测试图下发/虚拟时钟/记录留痕
```

| 存储 | 文件 | 内容 | 谁写 |
|---|---|---|---|
| Mock 记录库 | `data/mock.sqlite` | 票据（tickets）/ 预约（reservations）/ 缴费（payments） | mock 服务 |
| Web 用户库 | `data/web.sqlite` | 用户（users）/ 聊天消息（messages，含引用片段） | server |
| Agent 记忆 | `data/checkpoints.sqlite` | LangGraph SqliteSaver 全部 thread 会话 | agent |
| 向量库 | `kb/chroma_db/` | 知识库 45 个 chunk 的嵌入向量（gitignored，可重建） | kb 建库脚本 |

### 1.2 三条请求链路（数据怎么流）

1. **聊天链**：浏览器 → `POST /api/chat` → server 查用户在 mock 的车辆状态（拼「当前用户车辆」块）
   → Agent 调用（RAG 检索规章 + 注入「当前时间」块 → 主脑决策 → 按需调用工具 → mock 落库）
   → 返回回复 + 引用片段，消息存 `web.sqlite`。
2. **识别链（管理端）**：识别栏上传图片（模拟硬件抓拍上传）→ 本地 OCR ∥ 视觉模型双通道
   → 仲裁 → 识别成功**自动触发闸机动作**（按所选区域登记入场 / 出口结算出场）。
   对话端不提供监控画面查看（车主越权请求会被如实拒绝）。
3. **看板链**：前端每 5 秒轮询 `GET /api/lots`（server 透传 mock）→ A/B/C 余位实时刷新；
   调试弹窗经 `/api/debug/*` 直接改 Mock 真实状态。

### 3.2 `common/` —— 共享基础设施

| 文件 | 功能 |
|---|---|
| `common/rates.yaml` | **费率单一事实源**：免费 15 分钟、计费单位 30 分钟、标准时段 07:00–22:00、三车型费率（3/5/8 元每 30 分钟）与封顶（30/45/60 元）、月卡统一价 300 元/月（30 天）、预约保留 30 分钟、A/B/C 区容量（30/60/60）。改任何数字必须同步语料与测试 |

| `common/config.py` | 三个模型的独立配置（`LLM` / `VISION` / `EMBEDDING`，各含 key/base_url/model/api_mode）。`langchain_kwargs()` 供 Agent 用；`client()` 返回 OpenAI 兼容客户端；`MOCK_BASE` 读 mock 地址。全仓库取模型配置只能经本模块 |
| `common/__init__.py` | 包声明（一行 docstring） |

### 3.4 `agent/` —— 智能体

| 文件 | 功能 |
|---|---|
| `agent/graph.py` | Agent 组装：`create_agent`（langchain 1.x 新接口）+ `SqliteSaver` 落盘记忆 + `RagContextMiddleware`。对外三个入口：`build_agent()` 组装、`chat()` 单问单答、`chat_with_trace()` 返回回复+引用片段、`chat_with_context()` 额外注入用户车辆上下文块 |
| `agent/prompts.py` | system prompt：职责范围、五条铁律（规章必须引用知识库并标编号；计费必须用工具；**不提供监控画面查看**；域外拒答；先结论后依据）、时间与日期规则、预约规则、用户车辆块使用规则、服务边界（面向车主、不播报监控动态）、典型流程 |
| `agent/tools.py` | 4 个 LangChain 工具（见 §4.3 映射表）；统一错误处理：工具内部不抛异常，一律返回 `{"ok": false, "error": {...}}`（mock 不可达 → `MOCK_UNREACHABLE`）。**不含监控/识别类工具**（车主服务边界） |
| `agent/vision.py` | **双通道车牌识别与仲裁**（管理端识别栏与相机测试链路共用）：本地 HyperLPR3 OCR ∥ 视觉大模型（含 429 退避重试），并行线程池执行；仲裁矩阵五分支（both_agree / both_conflict / ocr_only / vlm_only / failed）；`recognize_upload()` 供识别栏上传，`recognize_plate()` 读相机测试图；无缓存，每次真实识别；识别只读不写图 |
| `agent/rag.py` | 检索入口 `retrieve(query, k)`：嵌入查询 → Chroma 余弦检索 → 返回 `[{chunk_id, text, score, source, file}]`。Agent 对话与评测脚本共用同一函数，保证「评测口径 = 线上口径」 |
| `agent/rag_middleware.py` | RAG 上下文中间件：每次模型调用前取最后一条用户消息检索（短追问自动拼接上一轮 → 多轮语境化），把「当前时间」块（取 mock 虚拟时钟）、「当前用户车辆」块、规章片段拼进临时 system prompt（不写入历史）；命中写入线程局部存储供取证（`last_hits` / `last_error`）；检索失败静默跳过不阻塞对话 |

## 4. 智能体：模块组成与调用方式

### 4.1 模块组成（6 个文件）

| 模块 | 角色 |
|---|---|
| `graph.py` | 组装与入口：模型（ChatOpenAI，timeout 120s、max_retries 3）+ 5 工具 + 系统提示词 + RAG 中间件 + SqliteSaver 落盘记忆 |
| `prompts.py` | 行为规范：五条铁律 + 时间/预约/车辆块规则 + 服务边界 |
| `tools.py` | 工具层：5 个工具，错误统一转 `{ok:false, error}` |
| `vision.py` | 识别引擎：双通道并行 + 五分支仲裁（识别工具的实现） |
| `rag.py` | 检索实现：嵌入 + Chroma 余弦 top-k |
| `rag_middleware.py` | 检索自动化 + 上下文注入（时间块 / 车辆块 / 规章片段） |

### 4.2 一次对话的完整调用链

```
POST /api/chat {user_id, message}
 1. server 查用户 → thread_id = "web-user-{id}"（每用户独立记忆）
 2. server 调 mock GET /vehicle/{plate} → 拼「当前用户车辆」上下文块
 3. 持全局锁调用 chat_with_context(agent, thread_id, msg, 车辆块)
 4. RAG 中间件（每次模型调用前）：
     ├─ GET mock /debug/time → 「当前时间」块（不可达回退系统时间）
     ├─ retrieve(最后一条用户消息, k=3) → 规章片段块（短追问拼接上一轮）
     └─ 三块拼进临时 system prompt（不写入历史），命中存线程局部存储
 5. 主脑（LLM）决策 → 按需调用工具（可能多轮）→ 工具 HTTP 调 mock → mock 落库
 6. 返回最终文本 + 本轮引用片段 → server 存 messages 表 → 前端渲染（引用折叠）
```

### 4.3 工具 ↔ Mock 接口映射（Agent 触达停车场的唯一通道）

| Agent 工具 | 触达 | Mock 接口 | 说明 |
|---|---|---|---|
| `query_parking_status(area)` | 直连 HTTP | `GET /lots/status` | 车位查询（area 留空查全部） |
| `register_entry(plate)` | 直连 HTTP | `POST /entry` | 入场登记 |
| `calculate_exit_fee(plate)` | 直连 HTTP | `POST /exit`（`dry_run=true`） | 只报价，不改状态 |
| `reserve_spot(plate, reserve_time, area)` | 直连 HTTP | `POST /reserve` | 预约（超时 30 分钟自动释放） |

> **对话端不含识别/监控工具**：车主服务边界，看到监控画面属越权——识别只发生在
> 管理端识别栏（`/api/recognize`）；相机测试图（`/camera`）供测试脚本与双通道链路验证。

> 正式出场（改状态）由闸机动作路径执行：出口相机 cam-4 识别成功或网页上传选「出场验票」
> → server `_gate_action` 调 `POST /exit`；未结清费用 → `FEE_UNPAID` 拦截（先缴清后出场）。

### 4.4 记忆、并发与取证

- **多轮记忆**：SqliteSaver 按 `thread_id` 落盘 `data/checkpoints.sqlite`，Web 每用户一个线程、
  跨进程重启不丢（`tests/check_agent.py` 两个独立进程验证）。
- **并发模型**：server 单 Agent 实例 + 全局锁串行执行（聊天与识别共用锁）；
  中间件用 threading.local 存命中——锁下「写 → invoke → 读」同线程完成，天然隔离。
- **取证**：`chat_with_trace` 返回 `(回复, 引用片段列表)`，前端折叠展示、测试脚本断言引用编号。

### 4.5 三种调用方式


## 5. 知识库是怎样的

### 5.1 语料组织（人写的事实层）

- `kb/corpus/` 7 章：01 总则、02 区域与车位、03 费率与计费规则、04 月卡与优惠、
  05 预约规则、06 场内须知、07 FAQ（15 个小节）。
- 每章按 `## 章.节` 编号（如 `3.2 分时段费率标准`），小节 200–400 字、条款口吻；
  **费率数字与 `common/rates.yaml` 逐字一致**（由 `check_consistency.py` 逐项核对）。
- 当前切块结果 **45 个 chunk**（01 章 5 / 02 章 4 / 03 章 7 / 04 章 4 / 05 章 4 / 06 章 6 / 07 章 15）。

### 5.2 建库流程（`python kb/build_index.py --rebuild`）

```
kb/corpus/*.md（跳过 _ 开头文件）
 → parse_sections：按 "## 小节" 切分（编号 + 标题 + 正文）
 → make_chunks：去 markdown 符号 → 200–400 字一块（相邻块重叠 1 句）
 → chunk id = 小节编号-序号（如 3.2-01；无编号小节告警并用章节前缀）
 → 分批嵌入（EMBEDDING 配置组，text-embedding-v3，单批 ≤10，1024 维）
 → Chroma 持久化（kb/chroma_db，集合 parking_rules，余弦空间）
```

改动语料后必须：`--rebuild` 重建 → `eval_rag.py` 复测命中率 → `check_consistency.py` 过一致性。

### 5.3 检索与注入（运行时）

- 入口 `agent/rag.py: retrieve(query, k=3)`：嵌入查询 → 余弦相似度 top-k →
  返回 `{chunk_id, text, score(=1−距离), source, file}`。
- 中间件每轮对话自动检索并注入 system prompt（附 chunk id）；模型回答规章类问题时
  必须以片段为准并在末尾标注引用（如 `[3.2-01]`），前端把引用片段折叠展示。
- **多轮语境化**：当前问句短于 15 字（如「晚上呢？」）时，自动拼接上一轮用户消息一起检索。

### 5.4 评测与质量保障

| 机制 | 脚本 | 说明 |
|---|---|---|
| 命中率评测 | `kb/eval_rag.py` | 标注集 83 条：expected 任一 chunk 进 top-k 即命中；域外 5 条不计入分母；输出分类命中率与失败清单。验收锚点：Top3 ≥95% |
| 数据一致性 | `tests/check_consistency.py` | 29 项：① rates 每个费率数字必须出现在语料；② 编造条款黑名单（会员积分/首小时免费等不得出现）；③ 评测集标注的 chunk id 必须真实存在；④ rates 内部自洽（夜间价=标准价×50%、封顶/月卡 >0） |
| 域外拒答 | `tests/test_e2e.py` 情景 3 | 负责人电话/天气/写诗/餐厅/股票 5 问必须拒答且不含手机号 |

### 6.2 状态与持久化模型

| 层 | 内容 | 特点 |

- 价值：现场不可能真的等 2 小时——注入时间后计费照常计算。

  （绘制规格属 mock 相机链路，测试图生成在夹具侧、服务只下发）。
- **文档**：`docs/部署文档.md` §6（Mock 部署、调试端点、常见问题、接口清单）。
- **边界**：不实现计费逻辑（调 D 维护的 `common/pricing.py`）；不建知识库（B 的范围）。

### 8.4 D —— 其他所有（交付物）

- **基础设施**：`common/`（`rates.yaml` 费率单一事实源、`pricing.py` 唯一计费实现、
  `config.py` 三模型独立配置）。
- **智能体**：`agent/` 六个模块（graph / prompts / tools / vision / rag / rag_middleware）。
- **Web 后端**：`server/app.py`（用户/聊天/识别/看板代理/静态托管 + 闸机联动 + 车辆上下文注入）。
- **前端**：`web/`（Vue3 + Element Plus 四栏界面全部交互）。
- **其余测试**：`check_api`、`check_agent`、`test_vision`、`test_e2e`、`test_latency`、
  `test_resilience`、`prewarm`、`reset_all`。
- **集成与文档**：两服务联调、README、本文档、演示答辩支撑。

### 8.5 协作界面（三方对接的冻结约定）

| 对接 | 约定 |
|---|---|
| B ↔ D | 检索签名 `retrieve(query, k) -> [{chunk_id, text, score, source, file}]`（Agent 对话与评测共用）；chunk id 命名规则（`章.节-序号`）；Agent 引用标注格式 `[3.2-01]` 与语料编号一一对应 |
| C ↔ D | HTTP 接口与字段结构、错误对象 `{ok:false, error:{code,message}}` 与全部业务错误码；相机 id 与测试图命名约定（cam-1/2/3 入口、cam-4 出口；`{相机}_{变体}.jpg`，`/camera` 直接下发）；`/vehicle/{plate}` 字段供「当前用户车辆」块注入 |
| C ↔ B | 一切费率数字以 `common/rates.yaml` 为单一事实源：C 的计费读取与 B 的语料书写都必须与之逐字一致（由 check_consistency 守门） |
| 全员 | 演示前跑 `tests/reset_all.py` 复位；提交信息格式 `[模块] 一句话` |
