> 停车场管理智能体（parkade-agent）｜版本 v1.0
> 本文档目标：**干净环境按本文步骤可在 30 分钟内跑起系统**。
> 撰写分工：总体框架与 Mock 章节由成员B 撰写；Agent/前端章节由成员A 补充；知识库章节由成员C 补充。

## 3. 安装依赖

```bash
py -3.11 -m venv .venv
source .venv/Scripts/activate          # Git Bash；cmd 用 .venv\Scripts\activate.bat
pip install -r requirements.txt        # 全量安装
# 或精确锁版：pip install -r requirements.lock.txt
```

主要依赖分组说明：

| 分组 | 包 | 用途 |
|---|---|---|
| 服务框架 | `fastapi` `uvicorn[standard]` | Mock 服务 |
| HTTP | `httpx` | Agent 调用 Mock / 视觉 API |

## 4. 配置环境变量

```bash
cp .env.example .env
```

```ini
# 主脑
LLM_API_KEY=...            LLM_BASE_URL=...            LLM_MODEL=...
# 视觉（车牌识图）
VISION_API_KEY=...         VISION_BASE_URL=...         VISION_MODEL=...
# 嵌入（知识库）
EMBEDDING_API_KEY=...      EMBEDDING_BASE_URL=...      EMBEDDING_MODEL=...
```

自检：

```bash
python tests/check_api.py            # 三块逐块验证
python -c "from common.config import summary; print(summary())"
```

## 5. 启动服务

系统由两个进程组成，需开两个终端：

```bash
# 终端 1：Mock 停车场服务（端口 8000）
uvicorn mock_service.main:app --reload --port 8000

# 终端 2：Web 服务（含 Agent 与前端页面，端口 8100）
#   首次或前端有改动时先构建：cd web && npm install && npm run build && cd ..
uvicorn server.app:app --port 8100
```


## 6. Mock 服务部署说明（成员B）

本节按日常真实操作步骤撰写，可直接照抄执行。

### 6.1 依赖与准备

Mock 服务仅需 `fastapi` / `uvicorn` / `httpx` / `pyyaml` / `pillow`（随第 3 步一并装好）。
**不需要 API key、不需要向量库、不访问外网**，可在离线环境独立运行。

### 6.2 启动

```bash
# 项目根目录执行（必须是根目录，不能进 mock_service/ 里启动）
source .venv/Scripts/activate
uvicorn mock_service.main:app --reload --port 8000
```

- `--reload`：改代码自动重启（开发期用；演示/答辩可去掉）；
- `--port 8000`：默认端口，与契约约定一致；
- **务必在项目根目录启动**，因为模块路径写作 `mock_service.main:app`。

在 VSCode 中：按 `F5`（已提供 `.vscode/launch.json` 配置"Mock 服务 (uvicorn, 端口 8000)"），
或打开运行和调试面板选择同名配置后点绿色 ▶。

### 6.3 验证部署

```bash
curl http://127.0.0.1:8000/lots/status
```

期望返回（初始状态 A 区 free=27）：

```json
{"ok":true,"updated_at":"...",
 "areas":[{"area":"A","name":"地面区","total":30,"free":27,"occupied":3}, ...]}
```

浏览器打开 http://127.0.0.1:8000/docs 可看到全部接口并在线调试。

### 6.4 调试端点使用说明

Mock 服务提供 4 个调试端点，是**演示与测试的核心开关**：

#### `/debug/time` —— 虚拟时钟（计费演示的核心）

```bash
# 查询当前虚拟时间与偏移
curl http://127.0.0.1:8000/debug/time
# → {"ok":true,"virtual_time":"...","real_time":"...","offset_minutes":0}

# 方式一：绝对设置虚拟时间（演示"现在是某时刻"）
curl -X POST http://127.0.0.1:8000/debug/time \
  -H "Content-Type: application/json" -d '{"set":"2026-11-10T10:00:00"}'

# 方式二：相对快进（演示"过了 N 分钟"）
curl -X POST http://127.0.0.1:8000/debug/time \
  -H "Content-Type: application/json" -d '{"offset_minutes":120}'

# 时钟偏移归零
curl -X POST http://127.0.0.1:8000/debug/time/reset
```

**典型用法（演示计费）**：

```bash
# 1) 设为 10:00，入场
curl -X POST http://127.0.0.1:8000/debug/time -H "Content-Type: application/json" -d '{"set":"2026-11-10T10:00:00"}'
curl -X POST http://127.0.0.1:8000/entry -H "Content-Type: application/json" -d '{"plate":"京A12345"}'
# 2) 快进 2 小时
curl -X POST http://127.0.0.1:8000/debug/time -H "Content-Type: application/json" -d '{"offset_minutes":120}'
# 3) 报价 → 12.00 元
curl -X POST http://127.0.0.1:8000/exit -H "Content-Type: application/json" -d '{"plate":"京A12345","dry_run":true}'
```

> 现场不可能真的等 2 小时；注入时间后计费照常计算，这就是虚拟时钟的价值。

#### `/debug/reset` —— 全状态复位

```bash
curl -X POST http://127.0.0.1:8000/debug/reset
```

将**车位 / 票据 / 预约 / 记录库 / 时钟**全部恢复到契约 §5 定义的初始状态，演示可反复跑。
**v1.3 起票据/预约落盘 `data/mock.sqlite`：进程重启自动恢复在场状态与未过期预约**
（车已进场不会再因重启被"说成没进场"）；要完全回到演示初始请调用本接口。

#### `/debug/truth/{camera_id}` —— 真值对账（仅测试用）

```bash
curl http://127.0.0.1:8000/debug/truth/cam-1
# → {"ok":true,"camera_id":"cam-1","plate":"京A12345","vehicle_type":"小型车","variant_active":"normal"}
```

返回相机固定车牌，供测试脚本对账。**Agent 严禁调用本接口**（识别只许走 capture + 双通道）。

#### `/camera/{camera_id}/capture` —— 抓拍图（含变体）

```bash
# 浏览器直接打开查看
http://127.0.0.1:8000/camera/cam-1/capture                  # 清晰
http://127.0.0.1:8000/camera/cam-1/capture?variant=blur     # 模糊
http://127.0.0.1:8000/camera/cam-1/capture?variant=occluded # 中部遮挡
```

### 6.6 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: mock_service` | 未在项目根目录启动 | `cd parkade-agent` 后重试 |
| `ModuleNotFoundError: fastapi` | 解释器选错 / 未激活 venv | 激活 `.venv`，或在 VSCode 选 `.venv` 解释器 |
| `[Errno 10048] 端口被占用` | 已有服务在跑 | 先 `Ctrl+C` 停掉旧服务，或改用 `--port 8001` |
| curl 返回 422 | 缺 `Content-Type: application/json` | POST 请求务必带该头 |
| 中文乱码 | 文件编码非 UTF-8 | 编辑器统一存 UTF-8 |
| 车牌图字体异常 | 缺微软雅黑 | 确认 `C:/Windows/Fonts/msyhbd.ttc` 存在 |
| `schannel: CRYPT_E_NO_REVOCATION_CHECK`（git 相关） | 代理环境证书吊销检查失败 | `git config http.schannelCheckRevoke false` + `http.sslVerify false`（仅本仓库） |

### 6.7 接口清单（供部署核对）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/lots/status` | 车位状态（`?area=` 可选；含 `reserved` 预约保留，v1.3） |
| POST | `/entry` | 入场登记（预约车优先进预约区并自动核销，v1.3） |
| POST | `/exit` | 出场结算（`dry_run` 可选；落盘离开时间/费用/已缴费，v1.3） |
| POST | `/reserve` | 预约（即刻占位看板可见，v1.3） |
| GET | `/vehicle/{plate}` | 单车状态（在场/时长/预约/上次停车，v1.2/v1.3） |
| GET | `/records` | 进出场/预约/缴费留痕（`?plate=&limit=`，v1.3/v1.4） |
| POST | `/pay` | 缴费（现缴 spot / 月卡 monthly；月卡有效期内出场免计费，v1.5） |

| GET | `/debug/truth/{id}` | 真值对账（仅测试） |
| GET | `/debug/time` | 查询虚拟时间 |
| POST | `/debug/time` | 注入虚拟时间 |
| POST | `/debug/time/reset` | 时钟归零 |
| POST | `/debug/reset` | 全状态复位（含记录库清空，v1.3） |
| POST | `/debug/lots` | 看板调试（总车位/占用） |

## 8. Agent 与前端部署

**依赖**：`.env` 三个配置块齐全（`LLM_*` / `VISION_*` / `EMBEDDING_*`，见 `.env.example`），
先跑 `python tests/check_api.py` 确认三块全绿；知识库已建（§7）；Node 18+（Vue 前端构建用）。

```bash
# 链路自检（答辩前必跑：四相机识别 + 演示分支可达性 + 检索耗时）
python tests/prewarm.py

# Agent 自检（两轮对话 + 跨进程记忆，需 mock 在线）
python tests/check_agent.py --phase 1
python tests/check_agent.py --phase 2
```

**Web 版前端（Vue3 + Element Plus，主用）**：

```bash
cd web && npm install && npm run build && cd ..   # 构建（首次或前端改动后）

# 终端1：mock
uvicorn mock_service.main:app --port 8000
# 终端2：Web 服务（用户/聊天/识别/看板 + 托管前端）
uvicorn server.app:app --port 8100     # 浏览器打开 http://localhost:8100
```

界面五块：**用户面板**（添加/删除/切换用户，各用户独立对话历史与 Agent 记忆）；
**对话窗**（引用片段折叠展示）；**车牌识别**（上传抓拍图模拟硬件抓拍，走
本地 OCR ∥ 视觉模型双通道 + 仲裁，展示结果徽章与双通道明细；**识别成功即闸机联动**——
上传可选"入场（可指定 A/B/C 区或自动分配）/ 出场结算"，绿色提示条展示动作结果）；
**缴费**（现缴/月卡：现缴按当前出场费当场结清——仅在场车；月卡按车型月卡价办理 30 天，
有效期内出场免计费）；
**车位看板**（A/B/C 余位进度条 + 预约保留标签 + 5 秒自动刷新 + 「记录」弹窗：进出场/预约/缴费
留痕；调试弹窗：改各区总车位/占用数、设置虚拟时间、±2 小时、全部复位）。

前端开发模式：`cd web && npm run dev`（:5173，/api 代理到 8100）。

**运行说明与排障**：

- 多轮记忆落盘于 `data/checkpoints.sqlite`；Web 用户与消息历史存 `data/web.sqlite`；
  **Mock 进出场/缴费/预约记录存 `data/mock.sqlite`（重启自动恢复在场状态）**（均 gitignored）；
- **一键重置全部数据**：`python tests/reset_all.py`（重置 Mock 车位/记录/时钟 + Web 用户与对话
  + Agent 记忆 + 运行期图片；服务在线离线均适用，重置后刷新页面即可）——详见 README「一键重置」节；
- 上传图片存 `data/uploads/`（相机抓拍图 `data/captures/` 为 mock 侧链路产物），经 `/api/media/` 受控读取；
- **识别即闸机语义**：网页上传可选入场/出场（入场可指定区域），识别成功即执行（自动 `/entry` 或
  `/exit`）；mock 相机 cam-1/2/3 按物理位置为 A/B/C 区入口、cam-4 为出口（Agent 工具链路使用）。
  车已在场时重复入场识别提示"已在场内，未重复登记"（不失真，不静默改数据）；
- **缴费（现缴/月卡）**：`POST /pay`——现缴仅在场车（按当前出场费当场结清，不在场 400）；
  月卡按车型月卡价（300/450/600）办理 30 天、有效期内出场 `total=0` 免计费、重复办理 400；
  用户车辆上下文注入月卡状态（生效中/无），Agent 可答"我有没有月卡""我要交多少钱"；
- 识别链路的视觉 API 耗时数秒属正常（本地 OCR 亚秒级）；网关限流(429)时 LLM 调用自动退避重试；
- 向量库未建时对话仍可用（检索静默降级，需先按 §7 建库才有引用）；
- 看板调试直接改 Mock 真实状态（`/debug/lots`），Agent 查询实时同步；容量调整后 `/debug/reset` 恢复默认。
