## 0. 通则

- 服务地址：Mock 服务 `http://127.0.0.1:8000`，前端（Web 服务）`http://127.0.0.1:8100`。
- 编码 UTF-8；响应一律 JSON（相机图接口除外，返回 JPEG 字节流）。
- 金额单位「元」，数值型，保留 2 位小数；时间字符串格式 `YYYY-MM-DDTHH:MM:SS`（本地时间，不带时区后缀）。
- 车牌：省份简称 + 字母 + 5~6 位字母数字（如 `京A12345`）；统一去空格、字母转大写后处理。
- 成功响应一律含 `"ok": true`；业务错误一律 HTTP 400 + `{"ok": false, "error": {"code": "...", "message": "..."}}`；未知相机等资源不存在返回 HTTP 404 + 同结构。
- **错误码表**（不许自造新码）：
  `CAMERA_NOT_FOUND` `PLATE_NOT_FOUND` `ALREADY_INSIDE` `NOT_INSIDE` `RESERVE_CONFLICT` `INVALID_PARAM` `NO_FREE_SPOT` `FEE_UNPAID`（v1.6：出场时有未结清费用，闸机不予放行）
- **虚拟时钟**：服务内**所有**时间必须取自 `clock.now()`（`mock_service/clock.py`），全仓库禁止出现 `datetime.now()`（clock.py 内部除外）。检出自查：`grep -rn "datetime.now()" mock_service/`。
- 状态重置：`POST /debug/reset` 将车位/票据/预约/记录库/时钟全部恢复到初始状态（演示可反复跑）。
- **落盘纪律（v1.3）**：票据与预约的每次变更同步写入记录库 `data/mock.sqlite`（进入时间、离开时间、
  时长、费用、缴费状态、预约状态）；**进程重启自动恢复在场票据与未过期预约**——车已进场不会再因重启被"说成没进场"。

## 3. 接口明细

### 3.1 GET `/camera/{camera_id}/capture`

- query：`variant`（可选，默认 `normal`）；未知相机 → 404 `CAMERA_NOT_FOUND`。
- 返回：`image/jpeg` 图片字节流（Agent 的 `recognize_plate` 每次抓拍都真实执行双通道识别，无缓存）。

### 3.2 GET `/debug/truth/{camera_id}`

仅测试对账用。返回：

```json
{"ok": true, "camera_id": "cam-1", "plate": "京A12345", "vehicle_type": "小型车", "variant_active": "normal"}
```

**Agent 严禁调用本接口**（防作弊口径：识别只许走 capture + 双通道）。

### 3.3 GET `/lots/status`

- query：`area`（可选，A|B|C；不给则返回全部）。
- **`free` 口径（v1.3）**：`free = total − occupied − reserved`——被未过期预约保留的车位在看板上同步扣减
  （预约占用即时可见；过期预约自动释放，余位实时回补）。
- 返回：

```json
{"ok": true, "updated_at": "2026-11-10T12:00:00",
 "areas": [
   {"area": "A", "name": "地面区", "total": 30, "free": 27, "occupied": 3, "reserved": 0},
   {"area": "B", "name": "地下一层", "total": 60, "free": 51, "occupied": 8, "reserved": 1},
   {"area": "C", "name": "地下二层", "total": 60, "free": 58, "occupied": 2, "reserved": 0}
 ]}
```

### 3.4 POST `/entry`

请求体：

```json
{"plate": "京A12345", "camera_id": "cam-1", "area": "A"}
```

（`camera_id`、`area` 可选。不给 area 时按 A→B→C 找第一个有非保留余位的区。）

规则：同一车牌已在场（未出场）→ 400 `ALREADY_INSIDE`；全区无空位 → 400 `NO_FREE_SPOT`。

**预约联动（v1.3）**：有未过期预约的车 —— 不给 area 时**优先进入预约区域**（预约保留位可用时）；
入场即**自动核销预约**（status=consumed，看板 reserved 相应 −1）；指定 area 为预约区时，
按物理空位判定（保留位就是给它留的）。

返回：

```json
{"ok": true, "ticket_id": "T-0001", "plate": "京A12345", "area": "A",
 "entry_time": "2026-11-10T10:00:00", "reservation_consumed": false}
```

### 3.5 POST `/exit`

请求体：

```json
{"plate": "京A12345", "dry_run": false}
```

（`dry_run` 默认 false；`true` 时只报价、不改变任何状态——Agent 报价用。）
规则：车牌不在场 → 400 `NOT_INSIDE`；费用**必须**调用 `common/pricing.py` 的 `calc_fee()` 计算（mock 内禁止重写费率逻辑）。
**出场闸机规则（v1.6）**：出场前必须**已结清**当前费用——`出费 − 已结清 > 0` 时真出场返回
400 `FEE_UNPAID`（提示待缴金额，不予放行）；结清（缴费看板现缴，或月卡免计费）后出场放行。
`dry_run` 报价不受拦截（报价含 `paid_amount`/`due` 字段便于试算展示）。
**落盘（v1.3）**：真出场时记录「离开时间、时长、费用、缴费状态」入库。
**月卡（v1.5）**：持有效月卡的车 `calc_fee(..., monthly=True)` → `total=0`，返回 `monthly=true`。

返回：

```json
{"ok": true, "plate": "京A12345", "vehicle_type": "小型车", "area": "A", "ticket_id": "T-0001",
 "entry_time": "2026-11-10T10:00:00", "exit_time": "2026-11-10T12:00:00",
 "duration_min": 120, "free_minutes": 15, "billable_minutes": 105, "units": 4,
 "subtotal": 12.0, "cap_applied": false, "total": 12.0, "paid": true, "monthly": false,
 "paid_amount": 12.0, "due": 0.0}
```

（`paid_amount` 票据累计已结清金额、`due` 待缴金额，v1.6。）

### 3.6 POST `/reserve`

请求体：

```json
{"plate": "京B88888", "reserve_time": "2026-11-10T18:00:00", "area": "B"}
```

（`area` 可选。）规则：同一车牌存在未过期预约 → 400 `RESERVE_CONFLICT`；保留至 `reserve_time + 30 分钟`。
**占位（v1.3）**：预约即刻占用该区一个保留位（`/lots/status` 的 `reserved` +1、`free` −1）；
未指定 `area` 时默认保留到第一个有非保留余位的区；过期自动释放。

返回：

```json
{"ok": true, "reserve_id": "R-0001", "plate": "京B88888", "area": "B",
 "reserve_time": "2026-11-10T18:00:00", "keep_until": "2026-11-10T18:30:00", "status": "active"}
```

### 3.7 时钟与状态调试

| 接口 | 请求 | 返回 |
|---|---|---|
| GET `/debug/time` | — | `{"ok": true, "virtual_time": "...", "real_time": "...", "offset_minutes": 120}` |
| POST `/debug/time` | `{"offset_minutes": 120}` 或 `{"set": "2026-11-11T09:00:00"}` | 同 GET |
| POST `/debug/time/reset` | — | 时钟偏移清零 |
| POST `/debug/reset` | — | 全部状态（车位/票据/预约/时钟/容量）恢复初始 |
| POST `/debug/lots` | `{"area": "A", "total": 50}`（改总车位）或 `{"area": "A", "occupied": 20}`（改占用） | `{"ok": true, "area", "name", "total", "occupied", "reserved", "free", "updated_at"}` |

**`/debug/lots` 规则（v1.1 新增，供 Vue 看板调试）**：
- `total`：≥ 当前占用数，否则 400 `INVALID_PARAM`；容量为运行期覆盖，`/debug/reset` 恢复 rates.yaml 默认；
- `occupied`：0..当前容量，越界 400；增占用补合成车牌 `京DBG{区}{序号}`，减占用优先移除合成车牌、其次移除无票据的初始车牌、最后移除有票据车牌（连同票据，保持"在场 ⇔ 有票据"）。<br>两个字段可同送（先 total 后 occupied）。

### 3.8 单车查询 GET `/vehicle/{plate}`（v1.2 新增，v1.3 扩展）

用途：Web 端用户档案登记车牌后，每轮对话注入"当前用户车辆"状态（是否在场/已停多久/预约/上次停车）。

返回（不在场，**v1.3 增 `reservation` 与 `last_visit`**）：

```json
{"ok": true, "plate": "沪C66666", "inside": false, "area": null, "vehicle_type": null,
 "ticket_id": null, "entry_time": null, "duration_min": null, "queried_at": "2026-10-14T00:12:00",
 "reservation": null,
 "last_visit": {"exit_time": "2026-10-13T18:05:00", "duration_min": 125, "fee": 12.00, "paid": true}}
```

返回（在场）：

```json
{"ok": true, "plate": "沪C66666", "inside": true, "area": "A", "vehicle_type": "小型车",
 "ticket_id": "T-0001", "entry_time": "2026-10-14T00:12:08", "duration_min": 120,
 "queried_at": "2026-10-14T02:12:32",
 "reservation": {"reserve_id": "R-0002", "area": "A", "reserve_time": "2026-10-14T00:00:00",
                 "keep_until": "2026-10-14T00:30:00", "status": "active"},
 "last_visit": null}
```

- 任意车牌可查（未知车牌返回 `inside:false`，404 不适用——车牌非资源标识）；
- `duration_min` 按虚拟时钟计算；无票据的初始驻车车牌 `ticket_id/entry_time/duration_min` 为 null；
- `reservation`：未过期预约（无则 null）；`last_visit`：最近一次正常结算的出场记录
  （离开时间/时长/费用/缴费状态；无则 null，调试移除产生的空结算记录不参与）；
- `monthly`（v1.5）：生效中的月卡 `{"payment_id": "...", "valid_until": "..."}`；无则 null；
- `due`/`paid_amount`（v1.6，在场时）：待缴差额 / 票据累计已结清（出场闸机校验口径）；
- **Agent 不得用本接口替代 `recognize_plate` 做"识别"**；本接口仅限 Web 服务层为用户注入状态。

### 3.9 记录查询 GET `/records`（v1.3 新增，v1.4 增 payments）

用途：进出场 / 缴费 / 预约 全留痕查询（Web"记录"弹窗、测试对账）。

- query：`plate`（可选，按车牌过滤）、`limit`（可选，默认 20，1..100）。
- 返回 `tickets`（一票一行：进入时间/离开时间/时长/费用/缴费状态/active|closed）、
  `reservations`（一行一预约：预约时间/保留至/active|consumed|expired）与
  `payments`（一行一次缴费，v1.4），按时间倒序：

```json
{"ok": true, "plate": "京B88888",
 "tickets": [{"ticket_id": "T-0001", "plate": "京B88888", "area": "B", "vehicle_type": "小型车",
              "entry_time": "2026-10-14T10:00:00", "exit_time": "2026-10-14T12:00:00",
              "duration_min": 120, "fee": 12.0, "paid": 1, "status": "closed"}],
 "reservations": [{"reserve_id": "R-0001", "plate": "京B88888", "area": "B",
                   "reserve_time": "2026-10-14T09:00:00", "keep_until": "2026-10-14T09:30:00",
                   "status": "consumed"}],
 "payments": [{"payment_id": "P-0001", "plate": "京B88888", "type": "monthly",
               "amount": 300.0, "pay_time": "2026-10-14T19:00:00",
               "valid_until": "2026-11-13T19:00:00"}]}
```

- `paid` 为 0/1（SQLite 布尔）；在场中的票据 `exit_time/fee` 为 null、`status=active`；
- `payments.type`：`spot`=现缴（当场结清）/ `monthly`=月卡；`valid_until` 仅月卡有值（v1.5）；
- 记录存放在 `data/mock.sqlite`（gitignored）；`/debug/reset` 清空记录库。

### 3.10 缴费 POST `/pay`（v1.4 新增；v1.5 现缴+月卡；v1.6 结清联动出场）

用途：模拟车主缴费——**现缴**（结清当前待缴费用）与**月卡**（有效期内出场免计费）。
**不含预缴/冲抵语义**（v1.4 的预缴模型已废弃移除）。

请求体：

```json
{"plate": "京A12345", "type": "spot"}
{"plate": "京B88888", "type": "monthly"}
```

（`type` 默认 `spot`；月卡为统一价，无需指定车型。）

规则：
- **spot 现缴（v1.6）**：仅限在场车——缴纳额 = 当前待缴差额 `due = 出费 − 已结清`，入账票据
  （`tickets.paid_amount` 累加，出场闸机据此校验）；不在场 → 400 `NOT_INSIDE`；
  已结清（due=0）重复现缴 → 400 `INVALID_PARAM`（提示"已结清，无待缴费用"）；
- **monthly 月卡（v1.7）**：**统一价 300 元/月，不区分车型**（rates.yaml `monthly.price`），
  有效期 30 天（`monthly.valid_days`）；同车牌已有生效月卡 → 400 `INVALID_PARAM`（不重复办理）；
- `type` 非法 → 400 `INVALID_PARAM`。

返回（现缴）：

```json
{"ok": true, "payment_id": "P-0001", "plate": "京A12345", "type": "spot",
 "amount": 12.0, "pay_time": "2026-11-10T12:00:00", "duration_min": 120, "total": 12.0,
 "paid_amount": 12.0, "due": 0.0}
```

（`amount`=本次实缴（=缴费时的 due）；`paid_amount`=票据累计已结清；`due`=缴费后剩余待缴，v1.6。）

返回（月卡）：

```json
{"ok": true, "payment_id": "P-0002", "plate": "京B88888", "type": "monthly",
 "amount": 300.0, "pay_time": "2026-10-14T21:30:00",
 "valid_until": "2026-11-13T21:30:00", "monthly_active": true}
```

（月卡为统一价，返回不带 `vehicle_type`，v1.7。）

- **结清与出场（v1.6）**：出场闸机要求 `出费 − paid_amount ≤ 0`，否则 400 `FEE_UNPAID`；
  月卡车免计费（`total=0`）视同已结清；
- **`/vehicle/{plate}`** 返回 `monthly`（生效中月卡；无则 null）与在场时的 `due`/`paid_amount`；
  Web 车辆上下文注入费用状态（未结清待缴 N 元 / 已结清）与月卡——Agent 可答"我要交多少钱/能出场吗"；
- **缴费记录**：`payments` 表（`type`/`amount`/`pay_time`/`valid_until`）落盘 `data/mock.sqlite`，
  有效月卡随重启恢复；`/records` 的 `payments` 按时间倒序返回。

## 4. 计费规则（`common/pricing.py` 唯一实现，成员A 维护）

约定函数：`calc_fee(vehicle_type, entry_time, exit_time) -> dict`（返回字段与 §3.5 一致，不含 plate/area/ticket_id）。

规则（写死，测试按此断言）：

1. 免费 15 分钟（每次停车一次，从入场时刻起扣除）；
2. 扣除后按时间窗分段：**07:00–22:00 标准价，22:00–07:00 夜间价**（夜间价 = 标准价的 50%，见 rates.yaml）；
3. 每段时长独立向上取整到 30 分钟计费单位；
4. 封顶：按**自然日**分别汇总当日各段费用后应用该车型「当日封顶」；跨天则各日费用分别封顶后累加；
5. 月卡车辆（演示开关）总价 0。

工作示例（直接作为测试断言，成员B 抄进接口测试记录；均按「免费 15 分钟先扣、再分段、段内向上取整、按日封顶」实现，已由 `tests/test_pricing.py` 逐条跑通）：

| 场景 | 计算 | 应收 |
|---|---|---|
| 小型车 10:00→12:00 | 120−15=105 分 → 4 单位 × 3 元；未触封顶 | **12.00 元** |
| 小型车 21:30→23:10 | 免费扣至 21:45；段1（21:45–22:00）15 分 → 1×3=3；段2（22:00–23:10）70 分 → 3×1.5=4.5 | **7.50 元** |
| 小型车 11-10 21:00→11-11 01:00 | 免费扣至 21:15；段1（21:15–22:00）45 分 → 2×3=6；段2（22:00–24:00）120 分 → 4×1.5=6；11-10 合计 12（未触封顶）；段3（次日 00:00–01:00）60 分 → 2×1.5=3 | **15.00 元** |
| 小型车 07:00→23:00（封顶） | 免费扣至 07:15；段1 07:15–22:00 885 分 → 30×3=90；段2 22:00–23:00 60 分 → 2×1.5=3；当日合计 93 → 取封顶 | **30.00 元**（cap_applied=true） |
| 小型车 10:00→10:15（免费内） | 免费时段内出场 | **0.00 元** |

费率数字以 `common/rates.yaml` 为单一事实源；**语料（成员C）中所有费率数字必须与 rates.yaml 一致**，建库前逐项对账一次（测试报告含一致性用例）。

## 6. 知识库契约（成员C 对成员A）

- 目录：语料 `kb/corpus/NN_名称.md`（NN=01..07）；向量库 `kb/chroma_db/`（gitignored，脚本可重建）；集合名 `parking_rules`。
- **chunk id 规范**：`章.节-两位序号`，如 `3.2-01`；每 chunk 200–400 字，语义完整，相邻 chunk 重叠 1–2 句；不按固定字数硬切。
- 建库脚本：`python kb/build_index.py --rebuild`（先清后建）；embedding 分批 ≤10 条/批（DashScope 上限），模型 `text-embedding-v3`。
- 检索函数内部：嵌入调用必须经 `common/config.py` 的 `EMBEDDING`（独立配置组，见 §0 通则的配置约定），建库时按 `EMBEDDING_BATCH`（≤10）分批。
- **三个模型独立配置（全项目约定）**：主脑 `LLM_*` / 视觉 `VISION_*` / 嵌入 `EMBEDDING_*` 各用自己的一组环境变量，**禁止混用、禁止互相回退**；业务代码只能经 `common/config.py` 取配置，不得散落 `os.getenv("...API_KEY")`。
- **检索函数（签名冻结，不许改）**：

```python
def retrieve(query: str, k: int = 3) -> list[dict]:
    """返回按相似度降序的 top-k，每项：
    {"chunk_id": "3.2-01", "text": "...", "score": 0.83,
     "source": "3.2 费率标准", "file": "kb/corpus/03_费率与计费规则.md"}
    """
```

- 评测集 `kb/eval_set.csv` 列：`id,question,expected_chunk_ids,category,note`；expected 多个用 `|` 分隔；category ∈ {费率, 预约, 须知, 月卡, 多轮, 域外}。
- 评测脚本：`python kb/eval_rag.py --eval-set kb/eval_set.csv --k 3` → 打印总命中率、分类命中率、失败清单（含每条 top3 实际命中）。
- 命中率定义：**expected 中的任一 chunk 出现在 top-3 内即算命中**；总命中率 = 命中条数 / 总条数。
