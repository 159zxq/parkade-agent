# STORY.md —— Mock 服务答辩 2 页

> 场景：课程设计答辩，成员B 负责讲 Mock 服务模块。
> 目标：用 2 页说清"Mock 服务是什么、接口怎么设计"和"虚拟时钟这个技术亮点怎么让计费演示成立"。
> 受众：授课教师 + 同学。调性：学术可信、证据驱动、蓝白克制。

## 叙事主线

Mock 服务是全项目的"数据地基"——它代替真实的停车场硬件，为上游 Agent 提供可复现的数据基础。
两页分别回答两个问题：

1. **它长什么样？**（第 1 页：接口总览）—— 一页看清 10 个接口如何分层、覆盖哪些能力。
2. **它凭什么让演示成立？**（第 2 页：虚拟时钟）—— 这是全场最容易讲出"技术含量"的点。

## 每页要点

### 第 1 页：接口总览

- 一句话定位：Mock 服务 = 真实停车场的"行为等价替身"，10 个接口、4 类能力。
- 4 类能力分组：
  - **车位管理**：`/lots/status`、`/entry`、`/exit`、`/reserve`
  - **智能识别输入**：`/camera/{id}/capture`（三变体）
  - **调试支撑**：`/debug/truth/{id}`、`/debug/time`、`/debug/time/reset`、`/debug/reset`
  - 统一约定：成功 `ok:true`、错误 400/404 + 7 个标准错误码
- 底部结论：契约先行 → 10 接口字段冻结 → 上游 Agent 零适配接入。

### 第 2 页：虚拟时钟（亮点）

- 抛出问题：计费演示要"停 2 小时收 12 元"，现场不可能真等。
- 解法：全局单例 `clock`，业务时间 = 真实时间 + 偏移量；`set` 绝对设置 / `offset_minutes` 相对快进。
- 铁律：全仓库业务时间只取自 `clock.now()`，`datetime.now()` 仅许出现于 clock.py（grep 自查通过）。
- 演示链路（4 步）：设为 10:00 → 入场（票据记 10:00）→ 快进 +120min → 出场计费 12.00 元。
- 底部结论：时间注入让"计费逻辑"与"真实等待"解耦，演示可复现、可反复。
