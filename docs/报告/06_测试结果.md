## 6.5 延迟实测（`test_latency.py`）——分链路计账

> 口径说明：本系统识别链路含云端视觉 API，与对话链路延迟量级不同，故**分开测量、分别报告**。

| 链路 | n | min | avg | P50 | P95 | max |
|---|---|---|---|---|---|---|
| **对话链路**（检索 + 主脑回答，含工具调用回合） | 20 | 1.27s | **2.12s** | **1.96s** | **2.96s** | 3.56s |
| **识别链路**（本地 OCR ∥ 视觉 API + 仲裁） | 6 | 1.97s | 3.11s | 2.72s | 5.85s | 5.85s |

- 对话链路 **P50 1.96s ≤ 2s 目标达成**；P95 2.96s ≤ 3s 保底达成；首轮含冷启动（3.56s）；
- 识别链路受视觉 API 波动影响（2.0–5.9s），本地 OCR 通道单独为亚秒级（实测 7–534ms）；
- 明细：`docs/测试证据/latency_*.md`。

## 6.8 局限性与优化思路

1. **识别链路延迟受云端视觉 API 波动影响**（2–6s）。缓和手段：本地 OCR 已亚秒级承担主通道；视觉通道设 25s 超时 + 2 次退避重试；演示话术如实分链路计账。后续可换更快的视觉端点或加本地轻量 VLM。
2. **RAG 评测规模当前 25 条**（目标 60 条）。语料未全量（缺 02/04 章）时不虚报数字；补齐后全量重测并复核 Top-3 ≥95% 硬指标。
3. **双通道平票场景**：当前矩阵规定分歧以 OCR 为准（工程上更保守，因本地 OCR 对合成车牌置信度更高）。真实场景下可引入置信度加权或第三方复核。
4. **单机内存态 Mock**：重启即复位（演示场景反而是特性，`/debug/reset` 可显式复位）；生产化需接真实数据库与硬件。
5. **嵌入与主脑均为云 API**：断网即不可用。答辩预案为手机热点 + 录屏备份；长期可换本地嵌入模型（维度/接口已封装在 `common/config.py`，替换成本低）。
