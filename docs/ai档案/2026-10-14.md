# 2026-10-14 成员A —— 用户车牌字段 + 车辆状态注入对话（需求方新要求）

> 需求方指示（原文）：「每一个用户创建时都需要填写一个车牌，用于在回答时判断用户是否进入了停车场，停了多久。」

## 实现（AI 生成 → A 逐项实测）

### 后端
1. **mock 新增 `GET /vehicle/{plate}`**（契约 v1.2 §3.8）：返回 `inside/area/vehicle_type/ticket_id/entry_time/duration_min/queried_at`；任意车牌可查（不在场返回 inside=false）；时长按虚拟时钟计算；无票据的初始驻车车牌时间字段为 null。冒烟补 4 例（TC-Mock-30~32 + reset），全部通过——mock 冒烟现 **40/40**；
2. **server 用户表加 `plate` 字段**（建用户必填 + 格式校验，含旧库 `ALTER TABLE` 迁移）；
3. **聊天注入车辆上下文**：每轮对话前查 `/vehicle/{plate}` → 构造「当前用户车辆」块 → 经 `chat_with_context()` 注入临时 system prompt（不写入历史）；RAG 检索仍用用户真实问题（不被上下文块污染）；
4. **`agent/prompts.py`** 增「当前用户车辆」规则：以块为准、不反问车牌、与历史冲突时以块为准。

### 前端（web/）
- 添加用户弹窗：车牌必填（前端格式校验 + 禁用提示）；
- 用户列表项与对话头显示车牌标签。

### 关键缺陷与修复（本轮最有价值的一战）

- **症状**：HTTP 链路实测发现——车已入场（该问"停了多久"），但 Agent 仍答"不在场内"。
- **诊断过程**：① 标记实验（注入"暗号"上下文）证明注入机制本身通；② `/vehicle` 接口与上下文块构建逐项验证均正确（在场、90 分钟）；③ 精确复现锁定根因——**同 thread 内"历史惯性"**：模型上一轮说过"不在场内"，新一轮虽有正确的最新上下文块，仍沿用了自己的旧结论（注入块是最新的、模型却听历史的）。
- **修复**：强化注入块措辞——明确"**优先级最高；与历史对话中任何车辆状态陈述（包括你自己此前轮次的回答）冲突时，一律以本块为准，并主动更正此前的说法，不要沿用旧答案**"；prompts 同步。
- **修复验证**：同 thread 场景重放——轮1 不在场 → 轮2（已入场 90 分钟）Agent 正确回答"已停放 90 分钟"**并主动更正**："另外更正一下：我上一条回复说'车辆不在场'有误，以最新系统数据为准"；轮3 计费 6.00 元（虚拟时间凌晨→夜间价，正确）。
- **浏览器端全流程实测（车主小王 / 沪C66666）**：问"我的车在吗"→ 直接答不在场（**未反问车牌**）→ "让我的车入场"→ Agent 自动用档案车牌登记（T-0001）→ 看板按钮 +2 小时 → "停了多久"→ 120 分钟 → "要交多少钱"→ 6.00 元（夜间价 1.5×4 单位）。截图 `docs/测试证据/vue-user-plate-flow.png`。

## 备注

- 晚间再访实测：费用 6.00 元与白天 9.00 元均按虚拟时间正确切换夜间/标准价——分时段计费在真实对话链路中得到二次验证；
- 数据卫生：演示用户补车牌 `京A12345`（旧库迁移的用户无车牌 → 不注入车辆块，不影响对话）；测试用户已清理。

# 2026-10-14 成员A（第二轮）—— 记录库落盘 + 看板联动 + 移除 Streamlit（契约 v1.3）

> 需求方指示（原文）：「要有一个数据库记录进入时间，离开时间，缴费状态（离开默认已缴费）预约情况，
> 不然就算进场了也说成没有进场；车位看板在车辆进场时和被预约占用也不会有变化。」
> 另：「删除原有的streamlit」。

## 实现（AI 生成 → A 逐项实测）

### mock（契约 v1.3）
1. **新增 `mock_service/db.py`**：SQLite 记录库 `data/mock.sqlite` ——
   `tickets`（进入时间/离开时间/时长/费用/缴费状态 active|closed）、`reservations`（预约时间/保留至/active|consumed|expired）；
   每次状态变更同步落盘；`MOCK_DB` 环境变量可切库（测试隔离用）。
2. **重启恢复**：`State.restore_from_db()` 启动时恢复「在场票据 + 未过期预约 + 编号序列」——
   根治"车已进场、重启后查不到（被说成没进场）"。实测：入场 → 重启 mock → `/vehicle` 仍 `inside:true`（票号/入场时间完整）。
3. **看板联动**：`/lots/status` 增 `reserved`，`free = total − occupied − reserved`；
   预约即刻占位、过期自动释放、入场核销即时回补。**预约车入场自动进预约区并核销**（`reservation_consumed`）。
4. **出场落盘**：`/exit` 返回 `paid:true`（离开默认已缴费）并把离开时间/时长/费用写入记录库。
5. **`/vehicle` 扩展**：增 `reservation`（未过期预约）与 `last_visit`（最近结算：离开时间/时长/费用/缴费）。
6. **新增 `GET /records`**（进出场/缴费/预约留痕查询，支持 plate/limit）。

### server / agent
- `_vehicle_context()` 注入块扩展预约情况与上次停车（含缴费状态）——用户问"我缴费了吗/上次停多久"直接答；
- 新增 `/api/records` 透传；`prompts.py` 同步说明扩展字段。

### 前端（web/）
- 看板：B 区行显示「预约保留 N」标签；**5 秒自动轮询**（对话入场/预约后看板自动变化）；
- 新增「记录」弹窗：票据表（进入/离开时间、费用、在场|已缴费|未缴费）+ 预约表（有效|已核销|已过期），支持按用户车牌过滤。

### 删除 Streamlit
- `git rm app/`（streamlit_app.py）；requirements.txt 移除 streamlit；README/部署文档/测试报告同步改口
  （启动改为 mock:8000 + server:8100 两个终端）。

## 验证（全部实跑）

- mock 冒烟 **52/52**（新增 TC-Mock-40~47：预约占位/核销/记录落盘/重启恢复/reset 清库）；
- 计费 9/9、一致性 30/30、视觉 11/11、E2E 16/16（含浏览器全流程）；
- **浏览器实测（截图 `docs/测试证据/`）**：`vue-v13-board-autorefresh.png`（对话入场→看板 27→26 自动刷新、B 区预约保留 1）、
  `vue-v13-records-dialog.png`（T-0001 进入/离开时间/4.50 元/已缴费 + R-0001 有效）、
  `vue-v13-payment-status-qa.png`（问"停车费交了吗"→"已缴费 ✅ 91 分钟 4.50 元"并主动更正不在场）；
- 重启实测：`.venv` 重启 mock 后 `GET /vehicle/京B88888` 仍 inside（数据库持久化生效）。

## 备注

# 2026-10-14 成员A（第三轮）—— 修复"上传识别成功但未入场"（识别→闸机联动）

> 需求方反馈（原文）：「我在网页上传图片，就算识别成功，车位看板也不会变化，而且也没有记录，
> 问agent也说没有入场。」

## 根因

网页上传/相机抓拍此前只做**识别**（双通道+仲裁出车牌），不触发任何业务动作——
识别≠入场：看板/记录/Agen给车辆上下文当然都不变。用户预期是"闸机识别到车牌即放行"。

## 修复（server 层闸机联动，`server/app.py::_gate_action`）

- **入口相机 cam-1/2/3 与网页上传**：识别成功（仲裁出车牌）→ 自动 `POST /entry`（预约车
  自动进预约区并核销）；前端绿色提示「已入场：A 区 · 票号 T-0001（入场时间 …）」并即时刷新看板；
- **出口相机 cam-4**：识别成功 → 自动 `POST /exit` 真实结算（返回时长/费用/已缴费）；
- **防重复**：车已在场时重复识别 → 提示"已在场内，未重复登记"（mock 返回 ALREADY_INSIDE，
  不静默改数据）；不在场时 cam-4 → "不在场内，无法结算出场"；
- 响应新增 `gate` 字段（action/ok/message/ticket_id/...），前端 `applyRecognize()` 统一展示 + `loadLots()`。

## 验证（全部实跑）

- 样例图 `docs/样例/plate_京B88888.png` 上传 → 识别 both_agree → 自动入场 T-0001（A 区 27→26，记录库落 entering）；
- cam-4 出口抓拍（京A12345 已入场 120 分钟）→ 自动结算：120 分钟 / 12.00 元 / 已缴费，车位回补；
- cam-1 抓拍 → 自动入场；重复抓拍 → "已在场内，未重复登记"；
- **浏览器全流程**（截图 `docs/测试证据/vue-upload-autoentry.png`、`vue-upload-flow-agent-consistent.png`）：
  上传京A12345 → 绿条"已入场 A 区 T-0001" → 看板 27→26（自动刷新）→ 记录弹窗 T-0001 在列 →
  问 Agent "我的车现在在停车场里吗" → "**在的**，停在 A 区，入场时间 17:32:51，已停放 0 分钟，票号 T-0001"
  （并主动更正此前误报"已离场"）——识别、看板、记录、Agent 四方完全一致；
- mock 冒烟回归 52/52 全绿。

## 备注

- 闸机联动在 **server 层**（Web 模拟硬件链路），Agent 工具链路不变（Agent 仍走 register_entry 等工具）；
- 上传无相机 id → 按"入口闸机"处理（默认区域分配 A→B→C）。

# 2026-10-14 成员A（第四轮）—— 一键重置脚本 + 入场区域/出入口选择

> 需求方指示（原文）：「添加一个可以重置所有数据库，对话用户等到初始状态的代码到readme文档」
> 「为什么都是进入A区，不能选进入其他区域或出去？」

## 一、一键重置（scripts/reset_all.py，README 新增「一键重置全部数据」节）

覆盖四类运行期数据：
1. **Mock**（data/mock.sqlite + 内存 + 虚拟时钟）：在线走 `POST /debug/reset`；离线直接清库
   （下次启动即初始）；
2. **Web 用户与对话**（data/web.sqlite）：清空重建初始「演示用户（京A12345）」，
   sqlite_sequence 先清后插 → **用户编号从 1 重新开始**；
3. **Agent 记忆**（data/checkpoints.sqlite）：清空 SqliteSaver 全部 thread；
4. **运行期图片**（captures/uploads，`--keep-images` 可保留）。

参数 `--yes` 跳过确认。实测：在线/离线两分支、编号从 1、脏数据（入场+预约+用户+对话）全清。

## 二、入场区域 + 出入口选择（修复"都进 A 区"）

**根因**：入场请求不传 area → mock 按 A→B→C 找第一个空位（A 基本总有空位）→ 永远 A 区；
且上传动作写死"入场"，没有出场选项。

**修复**：
- **server**：`/api/recognize` 支持 `action=entry|exit` 与 `area=A/B/C|空`（**Form 字段**——
  实测坑：FastAPI 普通标量参数默认从 query 读，multipart 表单须显式 `Form(...)`，否则参数被忽略）；
  `_gate_action` 区域优先级 显式 area > 入口相机所在区（cam-1=A/cam-2=B/cam-3=C）> 自动分配；
- **前端**：上传区新增「入场 | 出场结算」切换 + 目标区域下拉（自动分配/A/B/C），
  出场结算时区域选择自动禁用；抓拍区加"相机按物理位置"提示。

**验证**：上传指定 B 区 → 进 B（B 51 空闲）；上传出场 → 结算回补；cam-2 → 自动进 B；
cam-3 → C；cam-4 → 结算；重复入场拦截。浏览器实测（截图 `docs/测试证据/vue-gate-area-select.png`）：
上传选 B 区 → "已入场：B 区 · 票号 T-0001"，B 区 52→51，A/C 不变；切出场结算 → 区域框禁用 →
识别 → "出口结算完成：1 分钟，应收 0.00 元（已缴费，可放行）"。
